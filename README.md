# Starfighter: The Void Vanguard (星海先锋)

> 一个基于 C++11 和 Raylib 的高性能 2D 弹幕射击游戏演示 (Tech Demo)。
> 专为展示 **现代 C++ 内存管理 (RAII)**、**对象池架构 (Object Pooling)** 以及 **数据驱动设计** 而设计。

## 🎮 核心特性 (Key Features)

### 1. 🚀 高性能对象池 (Object Pooling) [v0.2 New!]
* **痛点解决**：摒弃了传统的 `new/delete` 动态内存分配，解决了高频创建/销毁子弹和敌人导致的内存碎片化与 GC 震荡问题。
* **实现细节**：
    * **双重池化**：实现了 `Enemy` (容量100) 和 `Bullet` (容量30) 的双重对象池。
    * **预分配内存**：使用 `std::vector::reserve` 锁定内存空间，杜绝运行时扩容。
    * **O(1) 开销**：通过 `active` 标记位复用“死亡”对象，实现零运行时分配 (Zero Runtime Allocation)。

### 2. 📈 动态难度曲线 (Dynamic Difficulty) [v0.2 New!]
* **天道算法**：游戏难度随玩家分数线性增长，拒绝枯燥的重复劳动。
* **多维压制**：
    * **生成频率**：基于 `Score / 500` 的衰减公式，敌人生成间隔从 60 帧平滑压缩至 20 帧。
    * **移动速度**：基于 `Score / 100` 的增量公式，敌人速度无上限提升。

### 3. 🛠️ 工业级架构 (Entity Architecture & FSM)
* **状态机 (State Machine)**：引入 `GameState` 管理 `PLAYING` / `VICTORY` / `GAME_OVER` 状态流转，解耦物理与渲染。
* **实体组件**：利用 C++ **多态** 与 **虚函数** 实现 `Entity` 体系的统一管理。
* **配置驱动**：构建 `GameConfig` 命名空间，将所有硬编码参数提取为 `constexpr` 编译期常量。

## 🛠️ 技术栈
* **语言**: C++ 11/14 (GCC MinGW)
* **图形库**: Raylib 4.5
* **工具**: VS Code, Git

### 🗺️ 下一步冲刺计划 (Next Steps & Advanced Features)
> 经过前四个阶段的打磨，项目的基础架构已坚如磐石。接下来的冲刺，将全面展现“图形学”与“底层算法优化”的大厂核心竞争力。

* **[重点 2] 碰撞算法降维打击 (Spatial Partitioning)**
    * **目标**：打破目前子弹与敌人 $O(N \times M)$ 的双重循环暴力检测。
    * **技术点**：实现空间网格划分 (Spatial Grid) 或 四叉树 (Quadtree)，将碰撞检测开销降至近似 $O(N+M)$，支撑千人同屏弹幕。
* **[重点 3] GLSL 着色器编程 (Shaders & Post-Processing)**
    * **目标**：摆脱 4399 视觉感，提升游戏画面张力。
    * **技术点**：编写 Fragment Shader，结合 Raylib 的 `BeginShaderMode`，实现全屏泛光 (Bloom) 特效与 CRT 屏幕扭曲边缘效果。
* **[重点 4] DOD 进阶架构重构 (Structure of Arrays)**
    * **目标**：极致压榨 CPU 缓存性能。
    * **技术点**：将现有的 `ParticleSystem`（数组套结构体 AoS）重构为纯平面的 SoA (Structure of Arrays) 内存布局，向面试官展示对 L1/L2 Cache Miss 的深刻理解。
* **[重点 5] 贝塞尔曲线与镜头表现 (Bezier & Camera Shake)**
    * **目标**：提升游戏“打击感”。
    * **技术点**：为强力敌人引入三次贝塞尔曲线 (Cubic Bezier) 飞行轨迹；结合屏幕震动数学公式实现受击视觉反馈。
    
## 📅 开发日志 (Dev Log)
### 📅 [2026-2-22] 阶段四：化神·数据驱动与追踪武器系统
> **摘要**：深度重构武器系统，解决复杂对象池生命周期管理中的“夺舍（ABA）”问题，实装严格的向量数学追踪计算与动态状态机。

#### ✅ 今日完成 (Completed)
1.  **向量数学与防御性编程 (Math & Defensive Programming)**：
    * 实现了 `HOMING`（追踪导弹）的二维方向推演。通过计算 $Dx, Dy$ 及距离 $L$，运用 **向量归一化 (Normalization)** 确保导弹绝对飞行速度恒定。
    * 实装了底层除零防御逻辑（`L > 0.0001f`），杜绝了导弹与敌人坐标极度重合时引发的除以零（Divide by Zero）崩溃。
2.  **彻底攻克对象池“夺舍”陷阱 (Generational Index / ABA Problem)**：
    * 面对对象池复用带来的野指针/目标身份错乱问题，果断抛弃直接存储对象指针的做法。
    * 为 `Enemy` 类引入了 C++ 静态成员 `static next_id` 与实例成员 `unique_id`。子弹初次索敌时采用 **双重信物校验（Index 用于 $O(1)$ 寻址，ID 用于 O(1) 验明正身）**，完美保障了内存与逻辑的绝对安全。
3.  **动态杀戮状态机 (Kill Streak State Machine)**：
    * 在 `Player` 实体中解耦并剥离了武器判定。新增连杀计数器，实现了“击杀 5 敌武器升级，受击连杀归零且武器降级”的动态反馈机制。
    * 解决了对象池特有的**“脏数据污染 (Dirty State)”**现象，在子弹复活激活的瞬间强行重置 `vx/vy`，保障了状态流转的严密性。
4.  **工程素养与编译规范**：
    * 在 C++ 强类型要求下，清除了 `[-Wsign-compare]` (符号位比较隐患) 与 `[-Woverloaded-virtual]` (函数隐藏隐患)，实现了真正的 **Zero Warning (零警告)** 工业级编译标准。
